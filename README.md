# 07-revflow（冲流台）

冲流台 — 正向与冲正流水净额归并：正向装载 → 冲正关联入账 → 净额归并落余额 → 未平/超额隔离 → 流水净额与余额互证。

**不是** 多源 Feed 归并，**不是** 作业依赖编排，**不是** CDC 变更流，**不是** 质检签发，**不是** 数仓分层建设，**不是** 交班过户。  
**也不是** 收银/退款 CRUD 后台、电商订单、报表 CSV 看板——主链是**流水管道与净额状态**，不是业务单据编辑台。

## 主链

账户登记 → 装载正向流水 → 装载冲正并关联原单 → 跑净额归并（已配平落余额，未平/超额进隔离）→ 互证报告核对「流水净额 vs 账户余额」

## 多币种折算与钉扎汇率（fx_settle）

归并采用「开跑钉扎、趟内只读钉扎值」的汇率策略，杜绝实时牌价改写历史折算、同批重算净额漂移：

**汇率钉扎载体（二选一，本系统选定形态一）**：本趟汇率快照表 `fx_rate_snapshots` 按归并运行 id 落库，触发器禁止 UPDATE/DELETE，钉扎即不可变。

**折算取值路径（二选一，本系统选定路径 A）**：开跑把本趟涉及的「币种 → 记账币(CNY)」汇率一次性从牌价表 `fx_rates` 读出并写入快照；**写入快照后本趟禁止再读 `fx_rates` 牌价表**，所有折算只引用内存钉扎集与每条流水落库的 `fx_rate_snapshot_id`。后续牌价变动无法改写任何已归并流水的折算额、净额与余额；新趟只钉扎新快照，历史趟原样保留。

1. **开跑钉扎**：归并开始先一次性钉扎汇率集（挂 `settle_run_id`），缺任一币种牌价立即失败闭、整单回滚，绝不半折算留账。
2. **趟内只读钉扎值**：本趟所有正向/冲正的折算只取钉扎集，不回牌价表；每条流水落 `fx_rate_snapshot_id` + `converted_cents` 作为汇率证据，纯函数折算（ROUND_HALF_UP），同一流水键同趟结果稳定。
3. **折算证明实体（fx_conversion_proofs）**：基线所无、本回归新增。每趟每币种一行，挂归并运行 id 与钉扎快照 id，记录币种、钉扎汇率、折算前/折算后本币带符号合计、触及笔数；触及流水键（含账户、正负号、原币与折算额）落子表 `fx_conversion_proof_entries`。证明与快照、流水、余额同事务落库、同源，触发器禁止改/删；各币种折算后合计之和 == 账户折算净额合计 == `settle_runs.net_cents`。
4. **只读查询接口**：`GET /api/settle-runs/{run_id}/conversion-proofs` 按归并运行 id 返回折算证明（含触及流水键），接口只回证据、不做重算；运行不存在返回 404。
5. **失败闭原子切换**：整趟在单个事务内提交；缺牌价、中途异常或证明合计与净额不闭合均整单回滚，不残留进行中运行、半成品快照/证明或半折算账户。
6. **互证同源**：互证报告的钉扎汇率直接读落库快照（不回 `fx_rates`），按钉扎汇率逐条复算，并校验快照归属、折算证明同源闭合与跨趟余额守恒，禁止内存汇率表冒充证据。
7. **可查看**：归并台与账户界面展开某趟即可看到钉扎汇率、折算证明（含触及流水键）与每账户原币/折算净额，数据全部来自上述落库实体，与快照、流水、余额同源，不是只改展示文案。

牌价为 as-of 取值（`effective_at <= 钉扎时刻` 的最新一条）；新一趟只钉扎新快照，历史趟的快照、折算证明与折算结果不受后续汇率变动影响。
